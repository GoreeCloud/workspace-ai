## Correction and successful physical retest

The initial contrast patch in commit `8ddc9af` passed compilation and source tests, but **its physical Android 16 retest crashed immediately on launch**: the insets controller was queried before `setContentView`, when the Activity decor view was null. The second correction applies Android light status/navigation-bar icon flags **after** `setContentView(root)` and includes a source ordering assertion. The first failed correction is **not** considered verified. The corrected source at `ee2e16c` passed four native source contracts and both [Native Android QA run 39705744628](https://github.com/GoreeCloud/workspace-ai/actions/runs/39705744628) and [Checks run 39705744312](https://github.com/GoreeCloud/workspace-ai/actions/runs/39705744312). A newly downloaded, debug-signed APK was installed as a clean replacement for this disposable QA package. The native activity launched successfully, remained foreground with a running process, and **physical screenshot inspection confirmed dark, legible status-bar icons against the light background**. Reopening the Android keyboard retained the editor and disabled Send button above the keyboard. No new startup crash was observed in this test.

For future debug-only QA artifacts, GitHub's ephemeral debug signing key can vary between jobs. Do **not** disable signature checks or change device security. If `adb install -r` reports `INSTALL_FAILED_UPDATE_INCOMPATIBLE`, verify this is still the permission-free, disposable preview package and explicitly uninstall **only `com.goreecloud.workspaceai.nativeapp`** before installing the newer QA build. The starter has no persistent user data by design. A separately protected, persistent signing key is required before owner-facing upgrade releases.
